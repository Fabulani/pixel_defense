# Pixel Defense

2D tower defense in **Godot 4.7** (GDScript only, Mobile renderer, 720×720 base viewport, `canvas_items` stretch). Targets desktop, Android and Web, so every input feature needs both a mouse/keyboard and a touch path.

Hand-written first game with AI-assistance past the refactoring phase.

## Commands

There is no test suite or linter. CI (see "CI / releases") only checks that the project exports; verification is a headless load plus playing the game.

```sh
git lfs install && git lfs pull      # PNGs/fonts are in Git LFS; needed once after cloning
godot --headless --import            # (re)build .godot/ cache and parse all scripts
godot --headless --quit-after 120    # boot main scene for 120 frames; must print no SCRIPT ERROR
godot                                # run the game (main scene: main/main.tscn)
godot -e                             # open the editor
godot -- --seed=12345                # replay the generated map of that seed (integer >= 1)
godot -- --legacy-map                # play the hand-made map instead of a generated one
```

- On a fresh clone (no `.godot/`), the **first** `--import` reports a bogus parse error in `levels/level.gd` because autoloads are not registered yet. Run it a second time before trusting any error.
- The locally installed Godot may be newer than 4.6. Do not commit version bumps to `project.godot` or `export_presets.cfg` that the editor makes on its own.
- F1 in game reloads the current scene.

## Layout

Feature folders: a script, its scene, its `.tres` data and its sprites live together. There is no global `assets/` or `scenes/` folder any more; do not reintroduce one.

```
core/controls/   PanningCamera, CameraShake, TouchControls, KBMControls, SmoothDamp, InputController
core/managers/   building, currency, pathfinding, projectile, vfx, wave
core/vfx/        Flash helper and hit_flash.gdshader (shared by enemies and towers)
core/game_data.gd
entities/        bases, enemies (+ components), projectiles, spawners, towers (+ upgrades, hue_swap.gdshader)
levels/          level.tscn (TileMapLayer + tileset) and level.gd; generation/ (MapGenConfig, MapData, MapGenerator, MapPainter, default_map.tres)
main/            main.tscn / main.gd: entry point and composition root
ui/              hud, start_menu, game_end, highlight, tower_preview, tower_menu, mobile, themes
docs/            screenshots and asset licences (.gdignore'd)
```

## Architecture

**Autoloads** (`project.godot`): `CurrencyManager`, `PathfindingManager`, `GameData`. They have no `class_name` and are used by their autoload name. Their state survives `reload_current_scene()`, so `Level._ready()` re-initialises them (`coins = 5`, `PathfindingManager.setup(tile_map_layer)`). `GameData` also holds `requested_seed` (-1 = random each run), `legacy_map` (both set from the user args in `GameData._ready()` and deliberately kept across reloads, so restart and F1 replay the same map) and `map_seed` (seed of the loaded map, 0 for the legacy map; written by `Level._ready()`).

**Scene tree**

```
Main
├─ Level              TileMapLayer, PathfindingPreview (Line2D), PlayerBase,
│                     WaveManager, ProjectileManager, spawners (created at runtime on
│                     generated maps; EnemySpawner + EnemySpawner2 are the legacy map's)
├─ BuildingManager    towers are added as its children
├─ VfxManager         one-shot particle bursts and coin pop-ups, drawn above towers
├─ InputController
├─ TowerPreview, HighlightTile   (TowerPreview shows base + cannon ghost or the range ring)
├─ TowerMenu          CanvasLayer with upgrade / major / sell buttons above the selected tower
├─ PanningCamera      children: TouchControls, KBMControls, CameraShake
└─ HUD, GameEndScreen, StartMenu, MobileDisplayHandler
```

**`main/main.gd` is the composition root.** It injects cross-scene dependencies into `@export` vars and connects all cross-scene signals in `_ready()`. Siblings do not look each other up; new cross-scene wiring goes in `Main._ready()`. `Level` is a facade: Main and `BuildingManager` use its signals (`wave_started`, `enemy_count_changed`, `lost`, `won`, and the effect signals `bullet_fired`, `bullet_hit`, `enemy_died`) and methods (`start()`, `register_tower()`, `is_cell_buildable()`, `would_block_path()`) and never reach into its children. `Level` reports only the first outcome (`lost` or `won`). Inside a scene, dependencies are `@export` node references or `%UniqueName` / `@onready`.

**Input flow.** `TouchControls` and `KBMControls` turn raw events into signals (`tapped`, `clicked`, `pan_changed`, `pinch_changed`, `zoomed`, …) in `_unhandled_input`. `PanningCamera` consumes pan/zoom and smooths them through `SmoothDamp` (a `Resource` holding goal + spring state). `InputController` consumes tap/click and converts screen position to a tile cell. Both paths are always connected. `KBMControls` drops mouse events emulated from touch (`device == InputEvent.DEVICE_ID_EMULATION`), so a touch is handled once. A touch is a `tapped` only if it stayed under the drag threshold (3 mm, converted to viewport units per gesture), never had a second finger and was not cancelled; `clicked` needs a press and release within 8 px with no panning.

**Selecting and upgrading.** Tapping a cell with a built tower makes `InputController` call `cancel_preview()` and emit `tower_selected`; any other cell emits `tower_deselected` first. `Main` shows `TowerMenu` and the range ring (`TowerPreview.show_range()` draws only the ring and hides both ghost sprites (base and cannon); `show_at()` brings the ghost back; the ring is shown after `cancel_preview()`) and on deselect hides both, but only if a tower was selected, so the build ghost is left alone. On lost / won `Main` calls `TowerMenu.hide_menu()` and `InputController.cancel_preview()`. `TowerMenu` ignores button presses for 300 ms after its row was (re)built (double-press protection) and clears its tower before hiding (a hidden pressed button emits `pressed`). `TowerMenu` only emits `upgrade_requested`, `major_requested`, `sell_requested`; `Main` forwards them to `BuildingManager.upgrade_tower()`, `apply_major_upgrade()`, `sell_tower()`, which own all currency and tower changes. `tower_sold` makes `Main` call `Level.unregister_tower()` (frees the pathfinding cell, disconnects the projectile hook). Each button has a bottom-left caption `Label` (`lvl+`, `sell`, and `MajorUpgrade.caption`; ignores the mouse, Kenney font, white with outline; it dims with the button and is not recoloured by the major icon tint material). Major buttons use the cannon as icon (`icon` = `turret_texture`, `icon_tint` = `turret_tint`); the button row sits in an 8 px `MarginContainer` inside `%Panel`. Menu buttons are `Control`s, so the GUI consumes presses and touches on them before `_unhandled_input`; `KBMControls.clicked` / `TouchControls.tapped` do not fire for them, so nothing leaks to the cell below.

**Building is two-step:** the first tap on a valid empty cell shows the `TowerPreview` build ghost (base and cannon sprites at 0.5 alpha plus the range ring); a second tap on the same cell emits `build_requested` → `BuildingManager.place_tower()`. An invalid cell cancels the ghost and emits `placement_invalid`. Placement is valid when the cell is unused, the tile is `buildable`, and `PathfindingManager.would_block_path()` says spawner → base is still reachable. After `tower_built`, `Level` marks the cell solid, makes every node in group `"enemies"` recalculate its path, hooks the tower to `ProjectileManager`, and redraws the path preview.

**Waves.** `WaveConfig.generate()` (resource `core/managers/wave/default_waves.tres`, assigned to `WaveManager.config`; enemy variants are `WaveEnemy` sub-resources) builds an `Array[PackedScene]` (count = base + fibonacci(index) × 3; later variants overwrite earlier slots; first appearance as shown on the wave banner (banner = `first_wave` index + 1): dasher wave 4, fast 6, armored 7, regenerator 9, heavy 11, splitter 12; `mini` is never in a wave) and `WaveManager` deals it round-robin (enemy i to open spawner `(i + wave_index) % n`) to the spawners that are open for the wave. `Level.enemy_spawners` is an `Array[EnemySpawner]` handed to `WaveManager.setup()` (it connects them; `WaveManager._ready` runs before `Level._ready`). `EnemySpawner.first_wave` (0-based index, banner = index + 1) is the first wave a spawner takes part in; until then `set_active(false)` draws its flag at alpha 0.35 and `Level` hides its preview line. `WaveManager` owns the pacing: `start_spawning(list, spawn_delay, first_delay)` gets `delay * n` and `delay * (k + 1)` for the k-th open spawner, so the spawners alternate and the whole wave spawns at one spawner's rate (`spawn_delay` 1.0, minus `spawn_delay_step` 0.1 after each wave whose spawning completed, floor `min_spawn_delay`). The next wave timer starts when *all* spawners completed spawning, not when the wave is cleared. `WaveManager.alive_count_changed` is the total over all spawners (HUD count). `all_waves_done` (win) fires when the last wave was sent, no spawner is still spawning and the total alive is 0 (checked on every count change and when spawning completes; may fire more than once, `Level` guards; not while `WaveManager` leaves the tree, so a reload does not count as a win). `Level` draws one preview line per spawner (copies of the exported `PathfindingPreview`) and `would_block_path()` checks the path of every spawner, open or not; `PlayerBase.destroyed` fires on the first enemy that reaches the base (health is 1).

**Tower levels.** `Tower.level` is 0..5 (`TowerStats.MAX_LEVEL`). Effective stats (damage, fire rate, range) = base stats x (1 + 0.1 x level) x the major multiplier; turn speed = `TowerStats.turn_speed` x `MajorUpgrade.turn_speed_multiplier` only (no level bonus; rapid_fire 1.5, long_shot 0.6, big_boy 0.35); `TowerStats` (base) is never mutated, `Tower._effective_stats` is a copy rebuilt in `_apply_upgrades()` and pushed to `TurretComponent.configure()`. Upgrades 1-4 cost `TowerStats.cost x next level`; the 5th is a `MajorUpgrade` resource (`entities/towers/upgrades/`: `rapid_fire`, `long_shot`, `big_boy`; the tower scene lists the choices) costing `major_cost` (50). Levels 1-4 show the level as a number (`%LevelLabel`, Kenney font 32 px at scale 0.2, white with black outline, top-right corner of the tower; hidden at 0 and 5); a major sets the turret texture (drawn at `MajorUpgrade.turret_scale`, 0.8, via `TurretComponent.set_appearance()`; the normal cannon is 1.0), a hue-swap `ShaderMaterial` (`hue_swap.gdshader`) on base/turret/bullet (all three majors tint their bullet; `rapid_fire` and `big_boy` also swap the bullet texture) and the bullet texture. `Tower.total_spent` is kept by `BuildingManager`; selling refunds all of it.

**Combat.** `TurretComponent` tracks `Enemy` bodies in its detection area and turns the cannon toward the priority target's lead point (position + `Enemy.get_path_velocity()` x distance / `TowerStats.bullet_speed`, one iteration, knockback ignored) with `rotate_toward` at the effective `turn_speed` (deg/s). `ReloadTimer` is one-shot: its timeout only sets `_loaded`; a loaded turret fires (`shot(origin, angle)` along the cannon angle, then restarts the timer) on the first frame that *any* live enemy's lead point is within `TowerStats.aim_tolerance` degrees of the cannon, so an idle turret fires as soon as it is aimed. With no target for `idle_delay` s the cannon sweeps +-`idle_sweep_angle` around its angle at a fixed `idle_sweep_speed` (31.5 deg/s, same for every tower; visual only). `Tower` wraps that in a `ProjectileData` (`RefCounted`, carries damage, penetration and an optional bullet texture/material from the major upgrade) and re-emits `shot`. `ProjectileManager` instantiates the `Bullet`. Bullets damage anything with a `take_damage` method and die after `penetration` hits or on their lifetime timer.

**Game feel.** All effects are visual only and must not change tower stats, fire timing or bullet origin.

- *Wiring.* `Bullet.hit` → `ProjectileManager.bullet_hit` / `bullet_fired`, and `EnemySpawner.enemy_died`, are relayed by `Level`; `Main` connects them, `tower_built`, `tower_upgraded`, `lost` and `wave_started` to `VfxManager.play_*`, `Tower.play_placed()`, `PanningCamera.shake()` and `HUD.show_wave_banner()`.
- *Particles.* `VfxManager.make_particles()` (static) is the only place that constructs particle nodes (`GPUParticles2D`, 1 px texture, alpha fade ramp), so swapping to `CPUParticles2D` is a one-function change. Bursts are one-shot, freed on `finished` (plus a safety timer), capped at `max_live_bursts`; pop-ups at `max_live_popups`. `VfxManager` runs with `PROCESS_MODE_ALWAYS` so effects finish behind the end screen. Bullets build their trail with the same factory and hand it to their parent on death so it fades out.
- *Flash.* `Flash.play(sprite, duration, color := Color.WHITE)` tweens the `flash` uniform and sets the `flash_color` uniform that both `hit_flash.gdshader` and `hue_swap.gdshader` have (steel blue for armored hits, green for regeneration, white otherwise). Enemies own a permanent hit-flash material; towers without a major get a temporary one that is removed afterwards. Do not flash with overbright `modulate` (lost on Web, and it feeds the hue-swap saturation test).
- *Enemy death.* `Enemy.die()` is idempotent (`is_dying()`): it emits `died` once (coins are paid then), stops pathing, sets `collision_layer = 0` deferred, leaves group `"enemies"`, fades and shrinks the sprite to half its normal scale over 0.25 s, then frees. The HUD count, `wave_cleared` and the win therefore lag the kill by the fade. Bullets and `TurretComponent` ignore dying enemies.
- *Knockback.* `ProjectileData.knockback` = `TowerStats.knockback` × `MajorUpgrade.knockback_multiplier`; `Enemy.apply_knockback()` scales it by `EnemyStats.knockback_scale`, caps it, and `Pathfinding.move(delta, extra_velocity)` adds it after the path velocity (rotation untouched), decaying over 0.12 s.
- *Tower.* Recoil tweens only `%Turret`'s `Sprite2D.offset` (divided by the cannon scale), never `position`, `rotation` or `scale`. The placement squash tweens the base and cannon sprite scales back to their stored target scale; `set_appearance()` kills it. Recoil, knockback and trail (`trail_amount`, `trail_lifetime`, `trail_particle_scale`, colour = bullet tint) differ per major via `MajorUpgrade` exports.
- *Camera shake.* `CameraShake` (always processing) writes only `Camera2D.offset` (trauma² × noise ÷ zoom); `position` and `zoom` belong to `SmoothDamp`. It is triggered only on loss.

**Enemy effects.** (1) *Armor*: `EnemyStats.armor` / `min_damage_share`; `Enemy.take_damage` does `max(hit - armor, hit * share)` and flashes steel blue when armor reduced the hit. (2) *Healing*: `Health.heal()`, `Enemy.heal()` (up to `max_health`, not while dying) and `Enemy.damaged(amount)` (after armor, emitted before the hit reaches health, so before `died` on the killing hit). `take_damage(<= 0)` does nothing. (0) *Facing*: `Pathfinding` turns the body toward the path velocity at most `EnemyStats.turn_speed` deg/s (movement itself follows the path at once; `path_velocity` is kept for turret lead). On `_ready` it snaps to the first path direction unless `snap_to_first_path` is false; `EnemySpawner._create_enemy(..., facing)` sets that for death spawns, which start at the parent's rotation. (3) *Speed*: `Enemy.set_speed_factor(source, factor)` / `clear_speed_factor(source)` keep one factor per source (e.g. `&"dash"`); `get_speed()` is `stats.speed` times the product, so a dash and a future slow combine. `Pathfinding` reads `get_speed()` (its entity is typed `Enemy`). (4) *Ability components* (`entities/enemies/components/abilities/`, `Node`s reading their `Enemy` via `owner`, timer based, stop on `died`): `Regeneration` (heals `hp_per_second` in ticks after `delay_after_hit` without damage, green flash per healing tick via `Enemy.flash()`) and `Dash` (speed x`multiplier` for `duration` every `interval`, random first phase; tell = sprite stretched along the travel axis via `Enemy.set_stretch()`, applied only after the spawn tween and never while dying). (5) *Split on death*: `EnemyStats.death_spawn_scene` / `death_spawn_count`; `EnemySpawner._create_enemy()` is the only place that creates enemies (queue and death spawns). Death children are counted at once and added deferred (adding a physics body inside a bullet callback is an error) at the dead enemy's position plus a few px, before the parent is freed, so the alive count never reaches 0 and the win cannot fire early. Pending children are tracked and freed if the spawner leaves the tree first. A scene that spawns itself is refused with `push_error`; `Enemy.split_generation` (0 for queue spawns, parent + 1) limits death spawns to depth `EnemySpawner.MAX_SPLIT_DEPTH` (3) with a `push_warning`, so loops A -> B -> A end. `Dash` / `Regeneration` disable themselves with `push_error` if their owner is not an `Enemy`.

**Data.** Tunables are `Resource` subclasses saved as `.tres` beside the scene: `TowerStats`, `EnemyStats`, `Drops`. `Health` is also a `Resource`. Enemy variants (`basic`, `fast`, `heavy`, `armored`, `regenerator`, `splitter`, `mini`, `dasher`) are inherited scenes of `entities/enemies/enemy.tscn`, each in its own folder with its own sprite (copied from the Kenney pack), stats/drops `.tres` and, for abilities, a component child node; `modulate` stays white.

**Map generation.** `Level._ready()` (when `use_generated_map` and not `GameData.legacy_map`) calls `_generate_map()`: `_pick_seed()` (`GameData.requested_seed` if >= 1, else a random seed that is never 0) -> `MapGenerator.generate(map_config, seed)` -> `tile_map_layer.clear()` -> `MapPainter.paint()` -> `PlayerBase` moved to the base cell -> the scene's spawners are freed and one `EnemySpawner` per generated spawner cell is instantiated (`first_wave` from the config) before `WaveManager` in the tree. All of this runs before `PathfindingManager.setup()` and `WaveManager.setup()`. The seed is printed (`Map seed: N`) and shown on the end screen (`%SeedLabel`, hidden for the legacy map). `MapGenConfig` (`levels/generation/default_map.tres`, assigned to `Level.map_config`) holds all tunables (50x50 max, spawner count, island shape, lake/tree/decor shares, road wiggle, lamp spacing, farmland multiplier, `max_attempts` 20). After the level is ready, `Main` calls `PanningCamera.fit_rect(Level.get_map_rect())`: the camera centres on the map, zooms so it fits the viewport (0.9 for 50x50, 1 for the 45x45 legacy map) and lowers `min_zoom` to that zoom, so the player can zoom out to the whole map and no further.
- *Generator.* `MapGenerator` and `MapData` are pure data with a local `RandomNumberGenerator` per attempt (seeded from `hash([seed, attempt])`): no nodes, autoloads or global `randi`, so the same config and seed give the same map. Steps: island shape (always one island, a "pangea": an ellipse with random stretch and rotation plus coast noise, at least 2 water cells from the map edge, only the largest 4-connected land piece kept, attempt dropped below `min_land_share`), coast distance field (BFS from water), base (coast distance >= `base_margin`) and spawners (coast distance 2..`1 + spawner_edge_band`, water mask 0; the spawner count shrinks towards `spawner_count_min` if it does not fit), keep-out circles, lakes from the top noise values (coast distance >= 3, count scaled by land area), shore cleanup, dirt roads, trees (scaled by land area), lamps, validation, decoration. The tileset has no tile for diagonal water pinches or grass with water on opposite sides, so a grass cell may only have one of 13 water masks (`MapData.is_valid_shore_mask()`; a water side also sets its two corners). The cleanup turns offending cells into water or grass and removes lakes under 4 cells until stable. *Roads* (`_place_roads`): `AStarGrid2D` (no diagonals) over grass with water mask 0, cell weight `1 + road_wiggle × noise`; spawners are routed in order and each path is cut at the first existing road cell, so roads merge into a tree; cells next to a road cost +4 so roads do not run side by side. Base and spawner cells are road too. If a spawner has no route the attempt is dropped. Roads are cosmetic: road tiles are buildable and enemies keep their own shortest path. *Lamps* (`Cell.LAMP`, atlas (0, 9), not buildable, `movement_cost` 255): every `lamp_spacing` road cells, on a free grass cell beside the road (not next to a marker, not touching a second road cell), so they never block the road. Validation flood-fills (4-neighbour) from the base; if a spawner is not reached, or the cleanup does not converge, the attempt is dropped and the next one runs. After `max_attempts` a fallback map (square island, no lakes, trees, decoration or lamps; markers and roads only) is used (`MapData.used_fallback`). Cut-off grass pockets away from water become trees. Farmland: decoration total / 10 × `farmland_multiplier` (1.2) patches of 3..5 cells; the first centre is the nearest of a few tries within `keep_out_radius + 3` of the base (outside the keep-out), later ones start next to existing farmland, so the farms clump around the base. Land is never within 2 cells of the map edge; the island is not forced to reach that margin.
- *Painter.* `MapPainter` builds a lookup from water mask to tile by reading the tileset's terrain peering bits (terrain set 0: grass 0, water 1), using only `buildable` grass tiles; picks among equal tiles with an RNG seeded by the map seed. Roads use a second lookup from the 4-side road mask (`MapData.get_road_mask()`) to the dirt tiles (terrain 2); mask 0 is (3, 9). Water, trees (3 tiles), the lamp and decoration tiles are fixed atlas coords; ROAD and LAMP cells are never covered by decoration. Decoration (`MapData.decor`, drawn instead of the terrain tile): dirt dots, farmland patches near the base, small islands in lakes.
- *User args.* `godot -- --seed=N` and `-- --legacy-map` (see Commands). An invalid seed gives a `push_warning` and a random seed. The legacy map is the tilemap painted in `levels/level.tscn`; `Level.use_generated_map = false` also selects it.

**Tiles.** 16 px tiles. The tileset is embedded in `levels/level.tscn` with custom data layer 0 `buildable` (bool) and layer 1 `movement_cost` (int; `255` means solid). `PathfindingManager` reads `movement_cost` by name, but only `255` (solid) matters: all other values are unused, every walkable cell costs the same (no weights), rebuilds its grid on every `setup()`, and emits `grid_changed` from `set_cell_solid()` (enemy `Pathfinding` components and the path preview re-path on it). It also writes the tile size to `GameData.grid_cell_size`.

**Physics layers:** 1 enemies, 2 projectiles, 3 towers, 4 player base. Groups: `"enemies"`, `"towers"`.

**Pause.** `StartMenu` pauses the tree on `_ready` and `GameEndScreen` pauses on show; UI that must work while paused needs the right `process_mode`.

## Conventions

- Static typing everywhere: typed vars, params, return types, typed arrays/dictionaries. `:=` only when the type is obvious. Keep it warning-free (integer-division warnings were fixed on purpose).
- `class_name X extends Y` on one line, for everything except autoloads.
- Signals are `snake_case`, past tense, with typed parameters, and are connected in code (`_ready`), not in the editor. Handlers are `_on_<source>_<signal>`.
- Private members and methods start with `_`. Node-local wiring uses `%UniqueName`.
- Composition over inheritance: behaviour lives in component nodes/resources (`Pathfinding`, `Health`, `TurretComponent`) owned by a thin entity script.
- `##` doc comments for public API. Some older functions use `""" """` string docstrings; use `##` in new code.
- Movement belongs in `_physics_process`.
- Input actions are namespaced with `>`: `camera>pan`, `camera>zoom+`, `camera>zoom-`, `camera>pan_left/right/up/down`; plus `left_mouse` and `f1`.
- Tabs for indentation. Resources are referenced by `uid://`; when moving or renaming files, move the `.uid` / `.import` sidecar with them (use `git mv`, or do it in the editor).
- Edit `.tscn` / `.tres` / `project.godot` by hand only for small, obvious changes. They are generated by the editor and easy to corrupt.
- `.github/agents/godot_scripter.md` is a generic Copilot agent persona, not project documentation.

## CI / releases

- `.github/workflows/build.yml` is a reusable workflow (`workflow_call`: inputs `version`, `require_signing`; optional secrets `ANDROID_KEYSTORE_BASE64/_USER/_PASSWORD`). It runs a `check` job and an `export` matrix (windows, linux, android, web) and uploads artifacts `export-<platform>`, one file each, named `pixel_defense-v<version>-<platform>...`.
- `.github/workflows/release.yml` runs on tag `vMAJOR.MINOR.PATCH`: `meta` validates the tag strictly and requires the commit to be on `main`; `build` calls `build.yml` with `require_signing: true` (secrets passed explicitly); `release` creates the GitHub release with `gh release create --verify-tag --generate-notes` (custom "Downloads" text is prepended) plus `SHA256SUMS.txt`, and uses `--clobber` uploads on re-runs; `pages` deploys the web export (after `release`).
- Top-level `permissions: contents: read`; jobs raise only what they need (a called workflow cannot exceed its caller). Never put `${{ }}` context values inside `run:`; pass them through `env:`.
- One-time setup (Pages with Actions source, `v[0-9]*` tag rule on the `github-pages` environment, Android keystore secrets) and the release steps are in README "Releasing". Cut a release: `git tag v0.1.0 && git push origin v0.1.0`. Only tag releases are release-signed (`require_signing`); PR/main/manual builds get a throwaway Android debug key. Failure logs are `logs-*` artifacts (not `export-*`). `v0.0.0` is rejected (start at v0.0.1).

## Where the refactor stopped

Done so far: feature-folder layout, enemy components + stats resources, tower/turret split, `ProjectileData`, camera split into `TouchControls` / `KBMControls` / `SmoothDamp`, `InputController` extraction, explicit wiring in `Main`, `Level` facade, pathfinding `grid_changed`, `WaveConfig` resource, `GameEndScreen`, touch/mouse separation (issue #18).

Open items:

- Multiple spawners: on the legacy map the position of `EnemySpawner2` (cell (42, 42), bottom right) and `first_wave = 2` are placeholders; on generated maps positions and `first_wave` come from `default_map.tres`. `EnemySpawner2` was added to `levels/level.tscn` by hand (re-save once in the editor). Verified only by headless scenario runs, not playtested by a human. All spawners share one wave composition (no per-spawner enemy mix), nothing tells the player when a spawner opens besides the flag fading in, and enemies already walking when a tower walls them in are not handled.
- Map generation (pangea, roads, lamps, 50x50, camera fit) is verified by headless scenario runs (500 seeds: valid shores, roads with water mask 0 and connected to the base, lamps off the road, determinism; in-scene: lamps not buildable and solid, roads buildable and walkable, camera fit zoom) and looked at by the author in game; not on a phone or Web. All values in `default_map.tres` and the new `MapGenConfig` exports are placeholders. `spawner_count_max` is clamped by what fits on the island (with 10 requested, about 3.6 spawners per map).
- The fallback map in `MapGenerator` was never hit through `generate()` in the 500-seed run; it is checked only by calling `_fallback()` directly. Changing generation steps changes the map of every seed.
- The `%SeedLabel` node in `game_end_screen.tscn` was written by hand; re-save it once in the editor. Missing `uid://`s in hand-written files are added with `ResourceUID.create_id()` (header) plus the target's uid in each `ext_resource`.
- There is no seed UI (start menu field, replay button, Web URL parameter); seeds are set only with `--seed=N`, which a Web build cannot take.
- The per-attempt RNG seed is `hash([seed, attempt])`, an engine hash, so the map of a seed may change with the Godot version (not checked).
- Generation takes about 215 ms per map in a headless desktop run (about 1.3 attempts on average; shape cleanup and decor are the slow parts, roads about 6 ms); not measured or optimised on Web or Android.
- There is one base tower by design; variety comes from its upgrade paths (currently the three majors). `BuildingManager` and `TowerPreview` each `preload` the single tower scene / stats on purpose. There is no build bar or tower-kind harness (built and removed after playtesting, 2026-11-16).
- Multi-touch across the tower menu and the map is not coordinated: a finger held on a button does not block a second finger's map tap, and a pinch starting on a button cannot zoom.
- All values of the new enemies (armored, regenerator, splitter, mini, dasher), their coins and wave shares are placeholders and unbalanced.
- Enemies have no health bars, so armor and regeneration are only readable through the flash colours.
- Issue #11 (obstacle-breaking enemy) is not done.
- Tower upgrades / `TowerMenu` are verified only headless with injected mouse and touch events (real `Input.parse_input_event` presses on the menu buttons; no leak to `clicked`/`tapped`, no double handling). Not yet checked on a phone, mobile Web or touchscreen laptop, nor with a human looking at it: menu placement/size at zoom and near screen edges, the hue-swap colours, the level number label and the 0.8 cannon scale are reviewed only in desktop renders, not on a device.
- Tower costs, +10 % per level and the major multipliers are placeholders, not balanced.
- `HUD` has a `%DebugCoinsButton` ("+9999", `CurrencyManager.earn(9999)`), visible only when `OS.is_debug_build()`; it is a focus-less `Button`, so its presses do not reach the map.
- The `HUD` panel eats clicks where it overlaps the map (top right), so a tower under it cannot be built or selected there.
- On touch, a short drag that starts on a menu button still presses it (the camera does not pan). Closing the menu by tapping a cell also runs that cell's normal action (denied flash or build ghost).
- A fast double press on a button whose row then shrinks (the last major: three majors + sell become sell only) puts the second press on the map: it deselects the tower and may start a build ghost.
- `TurretComponent.configure()` restarts the reload timer with `min(time_left, new period)` and then restores `wait_time` (Godot's `Timer.start(time)` overwrites it), so an upgrade never delays the pending shot.
- Smooth rotation (enemy facing, turret turning, hold-until-aimed, target lead, idle sweep) is verified only by headless scenario runs, not playtested. All turn speeds, `aim_tolerance`, `bullet_speed` and idle sweep values are placeholders. The reload restarts only when a shot fires, so the real fire rate is a little under `shots_per_second` (frame wait plus turning time); kept on purpose. A fast enemy close to a slow cannon (big_boy) may stay outside the aim cone and never be shot; check in playtest. Enemy turning still looks abrupt at path corners; a lower `EnemyStats.turn_speed` makes enemies slide sideways because movement follows the path at once. Smoothing the movement itself (rounded corners) would be needed; not planned. Aim follows only the priority target; preferring the enemy needing the least turn belongs to issue #10.
- `TurretComponent._get_priority_target()` always returns the first target (TODO: targeting priorities, issue #10).
- The touch/mouse separation is verified only with injected events in headless runs. It still needs a check on a phone, on mobile Web and on a touchscreen laptop; if a platform sends its own synthesized mouse events with a real device id, one tap would arrive as both `tapped` and `clicked`.
- `export_presets.cfg` `application/console_wrapper_icon` points at `uid://bgfcsb8hwikmn`, which does not exist.
- `Level.waves_survived` is the number of waves *started*.
- Game-feel effects are checked by headless scenario runs and by the author playing on PC. Not yet checked: Web export (GPU particles and trails on the Compatibility renderer, first-emission stutter), Android frame rate in late waves, a phone screen. All effect values are first-pass, not tuned.
- Every bullet, muzzle flash and burst creates its own `GPUParticles2D` and `ParticleProcessMaterial`; nothing is pooled or cached. Measure on a device before optimising.
- There is no sound, and no setting to reduce flashes or screen shake.
- Dying enemies freeze mid-fade behind the win/loss screen (the tree is paused; only `VfxManager`, `CameraShake` and the wave banner keep running).
- Enemies removed by the base (`PlayerBase` frees them) get no death effect.
